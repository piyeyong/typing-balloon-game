## Goal

Deliver a desktop-first two-column typing-game layout that keeps the stage and visual keyboard primary, keeps all four game statistics and essential actions permanently available outside the stage, collapses settings and leaderboard by default, and degrades safely in narrow windows without implying touch/mobile gameplay support.

## Context

The implementation reorganizes the existing static browser game without changing its gameplay, scoring, pause, mode-switching, result, or leaderboard rules. Existing JavaScript-consumed IDs and keyboard `data-key` attributes remain stable and unique.

## Implementation Decisions

- **Source order:** `<aside class="game-sidebar">` is first in `.game-layout` and `.play-area` is second. Within the sidebar, the permanent game HUD, guidance/feedback, advisory, and essential actions precede the separate settings and leaderboard disclosures. The desktop grid renders this sidebar-first structure as a left rail beside the broad play region; the narrow layout preserves the same logical order as one column. No CSS reordering is used, so visual, keyboard, and screen-reader traversal agree at every width.
- **Breakpoints:** the layout uses a single column below `1024px` and a two-column grid from `1024px` upward. At `640px` and below, the permanent HUD becomes a compact two-column stat grid and actions wrap or become full-width as needed. The non-modal physical-keyboard/widen-window advisory is visible below `1024px` and hidden at or above it.
- **Sidebar positioning:** the sidebar and all of its sections remain in ordinary grid/document flow at every width. The whole sidebar is never sticky, including on desktop, so expanded settings or leaderboard content remains reachable in short viewports.
- **Disclosures:** settings and leaderboard use separate native `<details>/<summary>` elements with no initial `open` attribute. They appear after the permanent HUD/guidance/actions in source order. No JavaScript disclosure state is added.
- **Active-balloon resizing:** a `ResizeObserver` watches the balloon layer and coalesces updates through one scheduled animation-frame adjustment. The callback captures and then rechecks the current round generation and balloon identity, and clamps only the active balloon's horizontal placement to the layer's new bounds. It does not recreate the balloon, restart its round or CSS animation, or change vertical progress, target, timing, error state, score, streak, or lives. Missing, detached, completed, pop/miss-transition, and stale-generation balloons are safe no-ops; paused balloons stay paused. Observer and scheduled-frame cleanup are explicit and idempotent.
